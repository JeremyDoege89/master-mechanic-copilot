# M5 / M5U / M5O review

Findings ranked most severe first. All verified by reading the code and running focused probes (no files changed).

1. **Meta budget hard stop resets on every request.** The global analyzers hold no client, so each `bind()` mints a fresh `MetaClient` with `spend_usd=0` ([routes_vision.py](/home/dreamz/mmc/backend/mmc/api/routes_vision.py:96), [routes_uploads.py](/home/dreamz/mmc/backend/mmc/api/routes_uploads.py:70)). Verified: two successive `bind()` calls return different trackers, the second at $0 after adding $50 to the first. Scenario: unlimited keyframe/PDF/video calls each pass the $120 pre-check because spend never accumulates. Fix: create one process-wide `MetaClient`/`BudgetTracker` at startup and have `bind()` share it (the Baseten client already does this correctly).

2. **Response-cache keys collide across different inputs.** Spark image requests key on `base64[:32] + length` only ([spark.py](/home/dreamz/mmc/backend/mmc/meta/spark.py:111)); SAM video requests key on byte length with no content hash at all ([sam.py](/home/dreamz/mmc/backend/mmc/meta/sam.py:932)). Verified: two different 1024-byte JPEGs with the same header produce identical request SHAs. Scenario: replay of a second photo/clip silently returns the first one's components, meter reading, or masks at $0. Fix: key on the full `sha256` of the sent bytes, as `spark_open._image_stub` and SAM image already do.

3. **Paid calls log $0 when `usage` is missing, so the ledger never grows.** Non-streaming Meta calls only fall back to the estimate for SAM ([client.py](/home/dreamz/mmc/backend/mmc/meta/client.py:487)), Baseten never does ([spark_open.py](/home/dreamz/mmc/backend/mmc/meta/spark_open.py:337)), and unknown/empty usage costs 0.0 by design ([budget.py](/home/dreamz/mmc/backend/mmc/meta/budget.py:64)). Verified: three Spark calls with `usage={}` left spend at $0. Scenario: any API/proxy shape drift makes every call free in the ledger and the hard stop unreachable. Fix: when `actual <= 0` and the estimate is positive, book the estimate (as `call_stream` already does).

4. **CSV columns misalign, then move posteriors on wrongly paired values.** Parsing skips unparseable cells per column independently ([csv_logs.py](/home/dreamz/mmc/backend/mmc/upload/csv_logs.py:234)), but `derive_tests` joins columns by row index. Verified: one bad STFT cell made idle trim 8.5% instead of 10%, pairing idle RPM with a cruise trim. That outcome is submitted through the normal `test_result` fold, so the wrong posterior update is durable. The same path also hardcodes `disp_l: 2.0` for MAF plausibility ([csv_logs.py](/home/dreamz/mmc/backend/mmc/upload/csv_logs.py:316)), misjudging any non-2.0L engine. Fix: parse row-wise, dropping or null-marking the whole row; take displacement from the session vehicle.

5. **Fallback primary is "corroborated" by itself, at double Baseten cost.** The keyframe path runs the primary (with Spark Open fallback inside, [spark.py](/home/dreamz/mmc/backend/mmc/meta/spark.py:185)) concurrently with an independent second-opinion call on the same client ([routes_vision.py](/home/dreamz/mmc/backend/mmc/api/routes_vision.py:204)). Verified with a failing Meta transport: Baseten was called twice for one image and the merged result reported `corroborated`. Fix: if the primary record has `provider: baseten`, skip the second opinion and label entries `single_source`.

6. **Vision routes ignore replay read-only mode.** Upload processing routes reject replay sessions ([routes_uploads.py](/home/dreamz/mmc/backend/mmc/api/routes_uploads.py:144)), but no vision handler checks mode ([routes_vision.py](/home/dreamz/mmc/backend/mmc/api/routes_vision.py:364)). Scenario: `POST /vision/keyframe` on a replay session spends live money (or fails) and appends evidence/observations into the replay log. Relatedly, `BudgetExceeded`/`NoCachedResponse` are never caught there, surfacing as 502/500 instead of 402, and SAM overlay failures including budget refusals are silently swallowed. Fix: add the same writable check and error mapping as the upload routes.

7. **Instrument readings bypass the audit log.** The instrument handler calls the analyzer unbound ([routes_vision.py](/home/dreamz/mmc/backend/mmc/api/routes_vision.py:447)), so Meta `llm_call` records are never appended (only Baseten fallback records are) and each call gets a fresh budget. This breaks the "log every request/response" rule for exactly the readings users confirm into evidence. Fix: `bind(session)` as the keyframe route does and append the returned record.

8. **`async` handlers run seconds of blocking work on the event loop.** Keyframe analysis (thread joins, SAM parsing) and video analysis (ffprobe/ffmpeg, network) are called directly from `async def` handlers ([routes_vision.py](/home/dreamz/mmc/backend/mmc/api/routes_vision.py:364), [routes_uploads.py](/home/dreamz/mmc/backend/mmc/api/routes_uploads.py:305)). Scenario: one video analysis stalls WebSocket state pushes and every other session for its full duration. Fix: move analyzer calls to a thread pool (`run_in_threadpool`/`asyncio.to_thread`).

9. **SAM downscaling makes replay caches miss across machines.** The SAM image cache key hashes the ffmpeg-downscaled bytes ([sam.py](/home/dreamz/mmc/backend/mmc/meta/sam.py:812)); with ffmpeg the fixture scales 0.5×, without it bytes pass through unchanged. Scenario: a cache recorded on a dev box misses on a judge box without ffmpeg and replay raises instead of replaying. Fix: key the cache on the original bytes and record the sent-bytes hash/scale as metadata.

10. **Android keyframes are PGM bytes mislabelled as JPEG, with stride ignored.** `handleFrame` copies the Y plane ignoring `rowStride` ([CameraScreen.kt](/home/dreamz/mmc/android/app/src/main/java/dev/dreamz/mmc/camera/CameraScreen.kt:142)) and `toJpegBytes` emits a `P5` PGM header ([CameraScreen.kt](/home/dreamz/mmc/android/app/src/main/java/dev/dreamz/mmc/camera/CameraScreen.kt:187)). `CameraScreen` is not yet wired into `MmcApp`, so this is latent: once wired, Spark/SAM receive non-JPEG data and overlays silently come back empty. Fix: respect plane strides and encode a real JPEG via `Bitmap.compress`.

11. **Sound detectors only examine the first second.** Tone peak search uses only chunk 0 ([engine_sound.py](/home/dreamz/mmc/backend/mmc/vision/engine_sound.py:249)) and hiss metrics only the first 1 s window ([engine_sound.py](/home/dreamz/mmc/backend/mmc/vision/engine_sound.py:284)). A squeal or hiss starting after the user walks to the engine is reported `normal`. Synthetic tests use stationary sounds, so they cannot catch this. Fix: search every chunk for candidate peaks and take the worst/best window for hiss.

12. **New threads append to a lock-free event store and budget.** M5 is the first threaded caller of `EventStore.append`, which does an unlocked seq/head read-modify-write ([event_store.py](/home/dreamz/mmc/backend/mmc/store/event_store.py:132)); `BudgetTracker.check/add` has the same check-then-add race under the concurrent fallback + second-opinion Baseten calls. Scenario: concurrent appends fork the hash chain or lose an `llm_call` silently (the vision `on_call` swallows all exceptions). Separately, one failing mask job discards all 25 overlays with no log ([sam.py](/home/dreamz/mmc/backend/mmc/meta/sam.py:524), delivered callback returns silently). Fix: lock appends and budget updates; collect per-frame mask results instead of failing the batch.

13. **`spec_id` changes the citation, never the outcome.** `evaluate` only relabels `expected.source` and copies min/max across ([evaluator.py](/home/dreamz/mmc/backend/mmc/engine/evaluator.py:36)); fuel pressure is still judged against hardcoded or caller-supplied limits. An uploaded manual range therefore cannot change any posterior, contrary to SPEC §5's source priority. Fix: compare measured values against the manual min/max where the test has a numeric expectation, or document that specs are display-only.

14. **`MetaClient` accepts non-Meta model IDs.** Only the `-contributor` suffix is refused ([client.py](/home/dreamz/mmc/backend/mmc/meta/client.py:211)); `MODEL_SPARK=gpt-4o` with a changed `META_BASE_URL` would be called. The Baseten client enforces its exact pin and is the model to copy. Fix: allowlist the pinned Meta IDs per key.

15. **Two tests pass without checking the claimed behaviour.** "No evidence before confirm" asserts only `tests_log == []`, which `compute_state` returns regardless of evidence ([test_vision_routes.py](/home/dreamz/mmc/backend/tests/test_vision_routes.py:139)); "both opinions logged" never reads the event log ([test_second_opinion.py](/home/dreamz/mmc/backend/tests/test_second_opinion.py:235)). Fix: assert on the session's `events.jsonl` (`evidence_added`/`llm_call` counts) instead of derived state.

No posterior is moved by any LLM output directly, no contributor IDs or secrets reach fixtures/logs, and safety gates remain planner code — those constraints hold. Spot checks run: `test_engine_sound.py` + `test_upload_csv.py`, 23 passed.

Verdict: Not ready — the budget guard, replay cache, and CSV pairing defects (findings 1–4) must be fixed before this can be trusted in front of judges.# M5 / M5U / M5O review
