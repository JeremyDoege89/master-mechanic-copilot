# M2 — ELM327 driver + simulator + transports (sim-only, Day 1 overnight)

Scope: AGENTS.md M2 sim half only. Real-vehicle recording is the owner's Day 2 job; every
item below is verifiable with JVM unit tests, no device needed. M0/M1 committed (`7de7161`).
No backend routes, no UI, no LLM calls. Do NOT: any ECU write, `AT TP A0`, non-Meta APIs,
probabilities outside `engine/`, full-VIN plaintext logs.

## 1. Files (exact paths)

Driver (`android/app/src/main/java/com/mmc/elm/`):
- `Allowlist.kt` — ALLOW first-bytes {01,02,03,05,06,07,09,0A}, blocked set
  {10,11,14,27,28,2E,2F,31,34,35,36,37,3D,85} + raw `ATMA`; `check(service, did, profile, token)`.
- `ClearToken.kt` — single-use token type (consumed on first Mode 04, reuse throws).
- `Parsers.kt` — `>` framing, `SEARCHING...` strip, typed errors (NO DATA, CAN ERROR,
  BUS INIT ERROR, BUFFER FULL, STOPPED, UNABLE TO CONNECT, `?`), multi-ECU (7E8/7E9),
  ISO-TP reassembly (`0:`/`1:`), PID bitmaps, DTC P/C/B/U, Mode 06 MID/TID/min/max, VIN.
- `Pids.kt` — decode formulas + SPEC §6 priority groups (fast ~5 Hz / slow 0.5 Hz sets).
- `Fingerprint.kt` — probe matrix (ATPPS, ATCRA 7E8, ATS0, ATAT1, ATSH 7E0, `22F190`
  echo-tolerance) → `adapter_profile` matching `packages/schemas/adapter_profile.json`.
- `Elm327Driver.kt` — init sequence per SPEC §6 (ATZ…ATRV, `ATSP0` never `AT TP A0`,
  `?` tolerated on optional cmds), single-flight queue, timeouts (1.5 s ATZ / 2 s first
  0100 / 300 ms steady), multi-PID ≤6 only if `profile.multi_pid`, polling groups.
- `Elm327Sim.kt` — 3 personalities × vehicle model × 7 scenarios (see §3).

Transports (`.../adapter/` behind one interface `Transport.kt`: `suspend fun transact(line): ByteArray`):
- `SimTransport.kt`, `ReplayTransport.kt` (timed transcript feed, indistinguishable shape).
- `ClassicRfcommTransport.kt` (SPP UUID `00001101-...-00805F9B34FB`),
  `BleTransport.kt` (FFE0/FFE1, FFF0/FFF1), `WifiTcpTransport.kt` (`192.168.0.10:35000`).
  All take injectable socket factories so tests use fakes, no device.
- `../session/Recorder.kt` — writes `.mmrec` zip (transcript+timestamps, events.jsonl,
  manifest.json with sha256) per SPEC §6 "Simulator and recorded sessions".

Config + fixtures:
- `config/mode22_allowlist.yaml` — starter read-only Ford DIDs (e.g. F190 VIN); expanded Day 2.
- `backend/tests/fixtures/transcripts/*.txt` — canonical golden transcripts (init-genuine,
  init-badclone, single-PID, multi-ECU, ISO-TP VIN, DTC, Mode 06, each error string);
  mirrored as android test resources.
- `backend/tests/fixtures/sessions/sim-healthy.mmrec` — one sim-recorded bundle for replay_check.

Tests (`android/app/src/test/java/.../elm/`, `.../adapter/`): `ElmAllowlistTest`,
`ParsersTest`, `FingerprintTest`, `Elm327SimTest`, `TransportTest`, `RecorderTest`.

## 2. Order of work

1. `Allowlist.kt` + `ClearToken.kt` + `config/mode22_allowlist.yaml` (no dependencies).
2. Golden transcripts first (test oracle), then `Parsers.kt` + `Pids.kt` (pure functions).
3. `Fingerprint.kt` → emits schema-valid `adapter_profile` (genuine/good_clone/limited_clone/obdlink).
4. `Elm327Driver.kt`: init → queue/framing/timeouts → polling/multi-PID gating.
5. `Elm327Sim.kt`: personalities → vehicle model → 7 scenarios.
6. `Transport.kt` + Sim/Replay first, then Classic/BLE/Wi-Fi against fake sockets.
7. `Recorder.kt` + commit `sim-healthy.mmrec`; `ReplayTransport` round-trip.
8. Full suite green; log decisions in `docs/DECISIONS.md`.

## 3. Acceptance criteria → tests

- Blocked services throw: `ElmAllowlistTest` — every blocked first-byte (10,11,14,27,28,
  2E,2F,31,34,35,36,37,3D,85, raw ATMA) throws; 01–0A pass; `AT TP A0` string absent
  (grep test); Mode 04 without token throws, with token passes once, reuse throws.
- Mode 22 gate: `ElmAllowlistTest` — 22 allowed iff `ALLOW_MODE22` AND `profile.mode22`
  AND DID ∈ yaml; denied otherwise (3 negative cases).
- Init per personality: `Elm327SimTest` — GENUINE/GOOD_CLONE/BAD_CLONE complete init;
  BAD_CLONE (`?` on ATPPS/ATR1/ATCRA, >2-byte truncation, no multi-PID) degrades to
  `limited_clone` without crash; GENUINE → `mode22=true`.
- Fingerprint: `FingerprintTest` — each personality maps to the expected kind/supports flags.
- Parsers byte-exact: `ParsersTest` — every golden transcript decodes to expected
  values; each error string maps to its typed result.
- All 7 scenarios: `Elm327SimTest` — healthy; maf_unplugged (MAF=0, P0102);
  iat_unplugged (−40 °C, P0113); vacuum_leak (idle +18 %, 2500 rpm +4 %);
  fuel_fuse_removed (no start); coil_unplugged(n) (Mode 06 counts + P030n);
  thermostat_stuck_open (plateau 70 °C, P0128). Warm-up: first-order to 95 °C, τ=300 s.
- Transports: `TransportTest` — all five implement the interface; Replay timing matches
  transcript deltas (±20 %); Classic/BLE/Wi-Fi connect via fakes (real sockets out of scope).
- Recording: `RecorderTest` — `.mmrec` contains all SPEC §6 members, manifest hashes verify;
  `ReplayTransport` re-feed reproduces the transcript.
- Real-vehicle AC (VIN/DTCs/10 PIDs → `.mmrec`): DEFERRED to owner Day 2 (PLAN.md owner task 7).

  default `ALLOW_MODE22=false`. SPEC's "genuine/OBDLink only" ≡ `profile.mode22`.
- BAD_CLONE `?`-set and truncation per AGENTS sim spec; fingerprint probe list per SPEC §6.
- Canonical transcripts live in `backend/tests/fixtures/transcripts/`, mirrored to android
  test resources (AGENTS test plan names the backend path).
- `minSdk 26` in `build.gradle` vs 29 in AGENTS.md: untouched in M2, flagged for M0 cleanup.
- `ClearToken` is a driver-level single-use type in M2; backend request/confirm flow lands in M4/M6.
