# M4 — GATE: Android live → backend → WS → next-test card → JSON report

Goal: live OBD on the Ford (or Sim) streams Observations to the backend, which appends
events, recomputes engine state, pushes it over WebSocket, and emits a JSON report.
No LLM calls: every Observation has `extractor=rule` from OBD parsing only.
M0–M3 committed (event store, .mmrec, engine/, kp/). Do NOT: ECU writes, Mode 04,
non-Meta APIs, LLM-set probabilities, images as evidence, plaintext full VINs.

## 1. Backend FastAPI (new `backend/mmc/api/`, wired into `main.py`)

- `POST /sessions {vehicle?, user_level, tools[], mode}` → `{session_id}`.
  Appends `session_started`; seeds hypotheses from KP priors (`origin=kp`).
- `POST /sessions/{id}/events {type, payload}` → `{seq, hash}`. Append-only;
  rejects unknown types and non-`event.json` payloads; every write goes through
  `store/event_store.py` (hash chain). OBD Observations arrive as
  `observation_added` (+ `evidence_added` for the raw PID/DTC payload).
- `GET /sessions/{id}/state` → `{hypotheses[], next_tests[], missing_evidence[], tests_log[]}`
  computed live from engine/ (`bayes` + `planner` + `stoprule`); never stored.
- `POST /sessions/{id}/tests/{test_ref}/result {measured, conditions, evidence_ids}`
  → `{test_result, updates[]}`. Runs `evaluator` → discrete outcome →
  `bayes.update` + `trace` entry; appends `test_performed`, `test_result`,
  `posterior_updated` atomically (one fails = none appended).
- `POST /sessions/{id}/report` → `{report_id, url}`; `GET /reports/{id}.json`.
  JSON only (HTML/PDF is M6); matches `report.json` incl. `reproducibility{}`.
- `WS /sessions/{id}/ws`: pushes full `state` after every appended event; client
  reconnect resumes via `GET state`. Out of M4 scope (429/501 or skip):
  vision, clear-codes, `POST /replay`, ASR proxy — M5/M6/M7.

## 2. Android (minimal Compose flow, no camera/voice yet)

Flow: Settings (backend URL, default `http://<dev-host>:8000`) → Transport pick
(Classic/BLE/Wi-Fi/Sim; Sim default for dev) → Connect (init + fingerprint,
show profile) → Live (PID strip ~5 Hz fast group, DTC list) → Next-test card
(rank #1 + expected result + safety-ack button when gated) → Record outcome
(measured + conditions → result POST → expected-vs-measured card) → Report
(fetch JSON, render summary + conclusion + top hypotheses).
New: `session/SessionClient.kt` (OkHttp + WS listener, base URL from
`SharedPreferences`/settings screen), `ui/live/*`, `ui/testrunner/*`,
`ui/report/*`. `Recorder.kt` keeps writing local `.mmrec` in parallel; on each
result POST also attach the `.mmrec` `blob_ref` via `POST .../blobs`.
Read-only: driver allowlist unchanged; no new request bytes.
