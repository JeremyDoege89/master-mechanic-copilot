## 1. Voice — ASR proxy, deterministic grammar, Android hands-free

- Spike first (gates the protocol, not the grammar): `scripts/spike_voice_asr.py`, owner-run outside the sandbox like `spike_meta_upload.py` (key from `~/.config/meta/model-api.env`, never printed; sandbox has no network/keys). It opens `ASR_REALTIME_URL` (`wss://api.meta.ai/v1/asr/realtime`) with `MODEL_ASR=muse-voice-transcribe-1.0`, streams a short PCM clip, prints upstream message shapes (session config incl. keyword-biasing field, partial/final events, usage/duration), and saves key-free fixtures to `backend/tests/fixtures/asr/` with `provisional: true`. Until the owner flips them live (M5U pattern), every test below runs on provisional fixtures + a fake upstream; a fixture test asserts the flag so provisional data is never mistaken for verified.
- Backend proxy: new `backend/mmc/meta/voice.py` (`AsrProxy`, injected `upstream_factory` seam for offline tests; upstream WS client library chosen when the spike lands — DECISIONS note per AGENTS.md §8 if it is a new dep; FastAPI serves the client side). New `WS /sessions/{id}/asr` in `api/routes.py` beside `/ws`: unknown session 4404, `mode==replay` 4409, public mode 4501 (paid live call, off on Modal). Android sends binary PCM16 frames (16 kHz mono, `AudioRecord` settings mirroring `EngineSoundRecorder`; spike confirms or the proxy transcodes) plus text control frames (`start`/`stop`). The proxy adds `Authorization` from `MODEL_API_KEY` upstream only — never to the client, events, or logs — and forwards partials verbatim for live captions.
- Biasing + events + budget: biasing list built at connect from the active pack (`sessions.get_pack()`: test refs spoken-form, hypothesis L1–L3 labels, outcome tokens, units — e.g. `trim_idle_vs_2500`, “unmetered air leak”, `volts`) via one `session_config()` function the spike pins. Each upstream final appends `asr_segment {text, duration_s, command}` through the registry (hash-chained, `_broadcast` state push); partials are never events. Cost: `estimate_asr(seconds)` pre-check + actual seconds on `get_tracker("meta")`; over-budget closes 4402 with a spoken error. No Spark Open fallback for voice (`fallback.py` already excludes it); transcripts never set probabilities.
- Grammar: new deterministic `backend/mmc/voice_commands.py` (no LLM): lowercase/punct-normalise, number-word parser (`twelve point four`, `plus/minus eighteen`, digits). Parse returns a typed intent or `unknown`; Android renders the pending card, backend re-parses on confirm (single source of truth, unit-tested in Python, mirrored by JVM tests on fixture strings):

  | Utterance | Intent → existing route (only on confirm where noted) |
  |---|---|
  | `next test` | Focus rank-1 `next_tests[0]` from `GET /state`; TTS reads its level instruction. No mutation. |
  | `log 12.4 volts` | Pending `{test_ref: focused, measured:{voltage_v:12.4}}` for `battery_voltage_rest_running` (`physics.voltage`). Confirm (voice `yes`/`confirm` or tap) → `POST /tests/{ref}/result`; `no`/`cancel` discards. |
  | `log idle trim plus eighteen` | Stages `idle_trim_pct:18` for `trim_idle_vs_2500` (`physics.trim_rpm_split` needs idle + cruise); TTS asks for the 2,500 rpm value, second `log …` completes it. Confirm disabled until both present. |
  | `repeat` / `read it again` | TTS re-reads the last spoken card. No backend call. |
  | `what's the risk` | TTS reads rank-1 `safety_gate` checklist title + `cost.risk`/minutes (`safety.GATE_CHECKLISTS`). Voice never acks a gate; ack stays the tap checklist, gated results still 409 pre-ack. |
  | `level one/two/three` | Client render-level switch only (`levels.py` texts); session `user_level` unchanged. TTS confirms. |
  | anything else | TTS “didn't catch that” + transcript shown. No route call. |

  Confirmation rule: `asr_segment` alone is audit only — nothing becomes `evidence_added`/`test_result` (hence no posterior move) until the confirm step calls the existing route, which re-validates runnability, gate ack, and evaluator outcome as today.
- Android: new `voice/RealtimeAsrClient.kt` (OkHttp WS to `/asr`, reuses `BackendUrls` + state-socket lifecycle) + voice UI in `MmcApp.kt`/`MmcViewModel.kt`: hold-to-talk button and hands-free toggle (continuous capture, upstream finals endpoint utterances), `RECORD_AUDIO` requested only on first voice tap (`EngineSoundSpec` pattern + plain mic explanation), captions line, pending-confirm card (parsed value, test name, Confirm/Cancel). Spoken replies via Android `TextToSpeech` (on-device; Voice Transcribe has no TTS, SPEC §4). Voice never triggers clear-codes.
- Tests: `test_voice_commands.py` (every table row + number words + unknown; trim two-step staging; confirm-required: `asr_segment` appended, zero `test_result`/posterior delta until confirm POST); `test_voice_proxy.py` (fake upstream: partials forwarded, finals → one `asr_segment` each, key absent from events/client frames, budget adds `duration_s × $0.18/h`, over-budget 4402, replay 4409, public 4501); JVM `VoiceCommandTest`/`RealtimeAsrClientTest` (fixture transcripts → pending maps, TTS text selection, hands-free toggle state).
