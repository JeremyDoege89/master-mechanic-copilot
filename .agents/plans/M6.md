Goal: same session renders L1≠L3, gated tests require a checklist, reproducible JSON/HTML/PDF report with labelled Wonder AI review, $0 web replay of a bundled session, public Modal URL in replay-only mode. On M0–M5 + upload + Spark Open. Rules kept: engine-only posteriors, hash-chained events, read-only ELM (Mode 04 only via gated ClearToken), Meta-only models, no secrets in repo.
Gaps closed: `build_report` is still the M4 stub in `sessions.py` (`_prompts_sha()` constant, one conclusion copied to all levels); no `report/`, `agent/`, `meta/wonder.py`, `safety.py`, `/replay`, `/budget`, `modal_app.py`; KP tests lack `instructions_by_level`; `compute_state` drops `min_level`/tools/gate from `blocked_tests`; `web/src` is M0 shells.

- New `backend/mmc/levels.py`, the only renderer: `hypothesis_label()`, `trace_text()` (fills `text_L1/L2/L3`, replacing today's `f"{label}: {outcome}"`), `instruction()`, `summary()`, `verbal_band(p)` ("Likely (~6 in 10)", SPEC §3). Deterministic templating over KP text + numbers, no LLM. `compute_state` uses it; state gains `instructions_by_level` per test and `blocked_tests` regain `min_level`, `required_tools`, `safety_gate`.
- Prompts: create `backend/mmc/agent/prompts/level_styles.md` (+ `system_v1.md` stub), the versioned style guide for Spark narration; M6 only pins/hashes it (§3). Future narration is schema-validated and may only reword `levels.py` strings, never numbers or probabilities.
- Tools questionnaire at session start: canonical `TOOL_OPTIONS` in `levels.py` (none/multimeter/test light/jack+stands/vacuum gauge/smoke machine/fuel pressure gauge/scope/enhanced scan tool, SPEC §3) + level labels served at `GET /meta/levels`; Android first-run onboarding and the web session form render from it (replacing Android's hardcoded 4 tools). Planner filters unchanged (tools/`min_level`/gate/performed already enforced); Android Live + web cards must render `blocked_tests` with reasons, never hide them.
- Acceptance: same session renders different instructions for L1 vs L3.

## 2. Safety gates as code, end to end

- New `backend/mmc/safety.py`: `GATE_CHECKLISTS` from SPEC §8/SAFETY.md (`engine_off`, `engine_running_outdoors`, `fuel_system`, `hot_coolant`, `lifting`, `hybrid_ev`, `none`) each `{title, items[], l1_extra[]}`; state adds `gate_checklist` to gated `next_tests`/`blocked_tests`. Enforcement stays code: planner blocks unacked gates, result route 409 until a `safety_ack` event names the gate (kept); Android + web disable Run/Record until all boxes tick, then POST the ack. Generalise Android `EngineSoundBody` into one `SafetyGateCard`; web mirrors it in the next-test card.
- Stop-and-see-a-pro (SPEC §8: flashing MIL, overheating, oil pressure, brake/steering, fuel smell, smoke, SRS/HV) becomes pure `safety.stop_triggers(state)` over DTCs/ECT; on hit, cards are replaced by the pro-referral banner on both clients. No prompt decides this.
- Clear codes (Mode 04): `POST /sessions/{id}/clear-codes/request` first snapshots DTCs (03/07/0A), freeze frame (02), Mode 06 as evidence, then returns `{token, consequences_text}` stating clearing erases freeze frame and resets readiness monitors so an inspection can fail until drive cycles complete; `POST .../confirm {token, typed_confirmation}` requires exact typed `CLEAR CODES`, engine-off/key-on attestation, single-use token (`secrets.token_urlsafe(32)`, 5-min expiry, session-bound, stored hashed, consumed on use) held as the driver's existing `ClearToken`; appends `codes_clear_requested` → `codes_cleared`. Backend never emits Mode 04; no planner/AI path offers clearing as a fix.
- Acceptance: gated tests show the checklist before they can run.

## 3. Report — JSON, HTML, PDF + Wonder review

- Move to `backend/mmc/report/build.py` + `templates/report.html.j2` (Jinja2 autoescape; declare `jinja2` in `pyproject`, DECISIONS note). Routes: `GET /reports/{id}.json|.html|.pdf`. PDF via `report/pdf.py`, a small stdlib PDF 1.4 text writer (same content, no new dependency); HTML print CSS is the fidelity fallback. Extend `report.json` (DECISIONS entry): `summary_by_level` from `levels.py` (three real texts); per-hypothesis trace (seq, expected, measured, LR, `lr_source`, `text_L1/L2/L3`); expected-vs-measured rows `{test_ref, expected{min,max,outcome,units}, measured, outcome, evaluator, source{kind:kp|physics|manual_page|mode06_limit, ref, content_hash}}` verbatim from `test_result` events; `ai_extracted` per evidence row (`extractor` starts `spark`/`muse-`); second-opinion `agreement`/`sources` (`vision_second_opinions`); `fallback_used` (any `llm_call` with `fallback.from=meta`); SAM overlay refs; `safety_notes`; truncated VIN only (`vin_last6`, full VIN never leaves `vin.py`).
- Reproducibility made real: `prompts_sha256` = sha256 over sorted `agent/prompts/*.md` (replaces `m4-no-llm-prompts`), plus `model_pins` (+`spark_open`), `kp_version`, `engine_version`, `log_head_hash`; `report_built` appended after save as today.
- Wonder: new `backend/mmc/meta/wonder.py`, exactly one `muse-wonder-1.0` call per report at `EFFORT_WONDER` (xhigh) via `MetaClient`; input is the finished report JSON; output validated vs `wonder_review.json` `{gaps[], narrative, agrees_with_top}` with the probability-key ban from `vision/components.py`; rendered under the literal heading "AI review — Muse Wonder (does not change the diagnosis)". It flags gaps only (test: posteriors byte-identical before/after). Shared Meta `BudgetTracker`-guarded; result cached via the `llm_call` disk cache and stored on the report, so replay/rebuild costs $0. On `BudgetExceeded`/API error the report still ships with `wonder_review: null` + explicit "AI review unavailable" line; no Spark Open fallback for Wonder.

## 4. Web Replay + Report viewer

- Backend: `backend/mmc/replay/runner.py` + `POST /replay {bundle_ref|session_id, speed}` verifies the `.mmrec` (`mmrec.verify`), creates a `mode=replay` session, folds `events.jsonl` through the normal append path; `GET /sessions/{id}/events?after_seq=` feeds the scrubber. With `REPLAY_USE_CACHED_LLM=true` both Meta clients are cache-only (miss raises, $0), enforced centrally in `meta/client.py`/`spark_open.py`, asserted by test.
- Web (`web/src`, SVG only, no new dep): `pages/Replay.tsx` (session id or `.mmrec` upload → blobs+`/replay`; seq scrubber + play/pause at bundle speed), `components/HypothesisChart.tsx` (posteriors over seq from `history[]`), next-test cards (L1/L2/L3 switcher, instructions, expected outcomes, blocked reasons, safety checklist), `components/SamOverlay.tsx` (keyframe + SVG mask paths), evidence drawer (AI-extracted badge, agreement), `pages/Report.tsx` (summary-by-level, trace, expected-vs-measured table, AI review, reproducibility; `.html`/`.pdf` links).
- Judge mode: "Open judge demo" (`/?judge=1`) POSTs bundled `sim-healthy.mmrec` to `/replay` and deep-links to its Report — one click, no upload, no keys; a real Ford bundle swaps in by file drop only.
- Acceptance: public URL replays a bundled session with zero API spend.
