# M5U Upload mode — plan (builds on M5 live-image vision; no redesign)

Sources: AGENTS.md API contracts / Meta client rules / Do NOT; SPEC §4 model map, §7 Upload mode; PLAN Day 3 (Fri Oct 30); DECISIONS M5 entries (verified Spark `output_text` JSON + usage shape; SAM Responses `stream=True`, one user message wrapping parts, `meta-sam-parser`, empty stream = not found, object-prompt-alone rule). Existing code reused as-is: `meta/client.py` (`call`/`call_stream`, sha256 disk cache, `REPLAY_USE_CACHED_LLM` $0 replay, budget guard, `call_record` key-free), `meta/spark.py`, `meta/sam.py` (`segment_image`/`track_video`/`check_video_bytes`, ≤3 objects, 50-frame min), `meta/budget.py`, `vision/{components,instruments}.py`, `api/routes_vision.py` (settable-analyzer pattern), `store/blobs.py`, `sessions.py` (append validates `evidence`/`observation`; only `test_result` folds posteriors), `engine/evaluator.py` (`evaluate(..., manual_spec=...)` exists, route never passes it — wired here).

2. Test inputs, self-made only (no service-manual pages): (a) one-page PDF with a spec table (fuel pressure, charging voltage, ECT plateau) written by a stdlib minimal-PDF writer inside the spike (`upload_spec_test.pdf`, deterministic bytes, committed with `SOURCE.txt` = "self-generated"); (b) short H.264 MP4 made with `ffmpeg -loop 1 -i backend/tests/fixtures/images/engine_bay_02.jpg -t 3 -c:v libx264 -pix_fmt yuv420p` (shape-checking only, committed as recipe in `SOURCE.txt`, clip itself gitignored if >1 MB).
3. Calls, in order: Files API upload PDF (`purpose="user_data"`) → `muse-spark-1.3` structured spec extraction (§2 schema as prompt contract + server-side validation); Files API upload MP4 → Spark video understanding (timestamped event list, §4 schema); SAM video segmentation with one box prompt on that MP4 (reuse `sam.track_video`, inline `input_file` path already verified in DECISIONS — spike only confirms file_id acceptance as a bonus, never blocks on it).
4. Save key-free raw responses under `backend/tests/fixtures/upload/`: `spark_pdf_spec_01.json`, `spark_video_events_01.json` (`call_record` dicts), `sam_video_upload_01.jsonl` (raw stream events). Every fixture carries `"provisional": true` + `"captured": null` until the owner run replaces them and flips both; code/tests must pass on PROVISIONAL shape and be re-checked after capture. Exit: all three calls succeed, exact Files-API + `input_file` shapes recorded in `docs/DECISIONS.md`, spend logged. Until then items 2/4 parse provisional fixtures only.

## 2. PDF manual / scan-tool pages → Spark → `SpecRange` → expected-value source

5. New schema `packages/schemas/spec_range.json` (+ `examples/spec_range.example.json`): `{spec_id, parameter, min, max, units, conditions?, page, source_blob_sha256 (content_hash), extractor}`; required `spec_id, parameter, source_blob_sha256, extractor`; `extractor="spark:spec_table_v1"`. A scan-tool PDF goes through the same extractor; non-table numeric readouts land as `parameter="scan_readout:<slug>"` ranges with `min==max` only when the page states a value, never invented.
6. `backend/mmc/meta/files.py`: `upload_file(client, data, filename, purpose="user_data") -> file_id` via the OpenAI SDK Files API on the same `base_url`/key; local cache `DATA_DIR/llm_cache/files/<sha256>.json` (key-free) so replay/offline runs reuse the id with no network; contributor-ID guard inherited from `MetaClient`.
7. `backend/mmc/meta/spark.py`: add `extract_spec_ranges(pdf_file_id, client, page_hint="")` and `summarize_video(file_id, client)` — prompt-constrained JSON + `jsonschema` validation exactly like `analyze_components` (no Responses `text.format` dependency), plus the `components.BANNED_KEYS` probability scan reused from `vision/components.py`. LLM never emits probabilities, likelihoods or posteriors.
8. `backend/mmc/upload/specs.py`: validate each range, attach `content_hash` of the source blob (sha256 from `blobs.put`), build `evidence` payload `{type:"manual_page", blob_ref, content_hash, spec_ranges:[...]}` appended as `evidence_added` (evidence schema tolerates the extra key; no new event type). Wire the expected source: extend `ResultBody` with optional `spec_id`; route resolves it from the session's `manual_page` evidence and calls `evaluator.evaluate(test, measured, manual_spec={ref:"p.<page>", content_hash, min, max, units})` so `test_result.expected.source.kind="manual_page"` wins over kp/physics per SPEC §5; `evaluator` applies manual `min/max/units` when present (small change + test). Unknown `spec_id` → 400, nothing appended.

## 3. CSV logs (Torque / Car Scanner / FORScan) — deterministic, no LLM

9. `backend/mmc/upload/csv_logs.py` (stdlib `csv` only): sniff dialect (comma/semicolon/tab, Torque `[GPS]`-style preamble skip), header map table `HEADER_MAP` covering the three exporters' names for RPM, ECT, IAT, MAF, MAP, STFT/LTFT B1/B2, O2 B1S1, voltage, load, speed → canonical PID + unit conversion (°F→°C, psi→kPa, g/s passthrough). Unknown columns ignored and reported; unparseable file → `ValueError` naming the missing time/RPM column.
10. Output: one `evidence_added` `{type:"csv_log", blob_ref, content_hash}` + `observation_added` per canonical series (feature = PID name, value = median, `conditions` from bucket, `extractor="csv:<exporter>_v1"`, confidence 1.0). Derived tests only through the existing evaluator path: bucket rows into idle (~650–900 rpm) vs ~2500 rpm for `trim_idle_vs_2500`, warm plateau for `ect_warmup_curve`, mean MAF for `maf_pid_plausibility`, rest/running voltage split — each submitted once via the same appends as `POST .../tests/{ref}/result` (`test_performed`+`test_result`+`posterior_updated`), skipped with a reported reason if already performed. Observations alone never move posteriors (matches `compute_state`).
11. Golden fixtures written by hand in this repo: `backend/tests/fixtures/upload/{torque_vacuum_leak,car_scanner_healthy,forscan_ect_stuck_open}.csv` (+ `.expected.json` each: series medians, derived outcome tokens), generated from the M3 sim scenario numbers so the vacuum-leak CSV must yield `lean_idle_normal_cruise`.

## 4. Photo + video upload

12. Photo: no new path — Android/backend reuse `POST .../blobs` → `POST /sessions/{id}/vision/keyframe` unchanged (Spark components + SAM overlays + observations). Upload-mode sessions simply call it without the on-device keyframe selector; `vision/keyframes.py` server helpers stay available for multi-photo dedup (sharpest of a burst wins).
13. Video: `backend/mmc/upload/video.py`: accept MP4/MOV only via `sam.check_video_bytes`; probe duration/fps/size with `ffprobe` (ffmpeg 6.1.1 present; no new dep); upload via `files.upload_file` → `spark.summarize_video` → validate against new `packages/schemas/video_events.json` `{events:[{t_start_s,t_end_s,label,sam_concept,box_hint?}]}` (probability scan applied). Pick ≤3 events; cut sub-clips with `ffmpeg -ss -t -c:v libx264 -pix_fmt yuv420p` into the blob store; call `sam.track_video(subclip, boxes=[box_hint] if given, concepts=[sam_concept], frames=max(50, round(duration*fps)), size=(w,h))`. Box hints are treated as unverified 0–1000 space until the spike confirms Spark's coordinate space; without a hint, concept-only tracking. Enforce SAM billing floor in the estimate (`estimate_sam_video`), reject clips whose estimate would breach the budget guard before any call. Result: `evidence_added {type:"video"}` + per-event observations (`visual_event:<slug>`, extractor `spark:video_events_v1`) + overlay records in the response; posteriors untouched.

## 5. Endpoints, Android, budget/caching

14. New `backend/mmc/api/routes_uploads.py`, registered in `main.py` beside `routes_vision`, AGENTS.md contract style (blobs first, processing second, so a failed parse never loses the upload):
    - `POST /sessions/{id}/uploads` (multipart `file` + form `kind=manual_pdf|scan_pdf|csv|photo|video`) → `{blob_ref, sha256, evidence_id, kind}` (32 MB cap reused; appends `evidence_added` with the matching evidence `type`)
    - `POST /sessions/{id}/uploads/pdf/extract {blob_ref}` → `{spec_ranges[], evidence_id}`
    - `POST /sessions/{id}/uploads/csv/parse {blob_ref}` → `{series[], derived_tests[], skipped[], evidence_id}`
    - `POST /sessions/{id}/uploads/video/analyze {blob_ref}` → `{events[], overlays[], evidence_id}`
    - Photo needs no new route (see 12). Settable-analyzer seam (`set_analyzer`) mirrors `routes_vision` so tests run offline on fixtures. All Meta calls go through one `MetaClient` built with `on_call` appending `llm_call`/`sam_call`; with `REPLAY_USE_CACHED_LLM=true` every call replays from the sha256 disk cache at $0 and a cache miss raises `NoCachedResponse` (never spends). `kind`/`model` pins come from env only; Standard IDs, contributor IDs refused by the existing guard.
15. Session mode: add `"upload"` to `sessions.MODES`, `packages/schemas/session.json` mode enum, and `CreateSessionBody` docs (SPEC §3 flow 8 already names it); upload routes accept `live|upload` sessions, replay sessions stay read-only for processing routes. Log the mode addition in `docs/DECISIONS.md`.
16. Android (no new permissions; manifest today grants only `INTERNET`): extend `session/SessionClient.kt` with `uploadFile(sessionId, uri-bytes, filename, kind)` (generalize `uploadMmrec`'s multipart code) + `extractPdf/parseCsv/analyzeVideo` POSTs; add an Upload entry in `ui/MmcApp.kt` using `rememberLauncherForActivityResult(ActivityResultContracts.OpenDocument)` with MIME `application/pdf, text/csv, image/*, video/mp4, video/quicktime` (system picker needs no storage permission), showing per-kind result cards (spec table with page citations, CSV series + derived outcomes, video events) and routing photos into the existing keyframe confirm flow. No CameraX/manifest changes.
